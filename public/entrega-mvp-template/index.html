Cómo lo hicimos

El trabajo realizado desde el kickoff hasta el MVP: una célula multidisciplinaria (PM, UX/UI, Fullstack y QA) con metodología ágil.

  1. Semana 0 · Planeación y alineación: Kickoff con el cliente, planeación integral (tiempo, recursos y alcance) y alineación de expectativas con todas las partes.
  2. Product Strategy · Descubrimiento y estrategia: Entrevistas con stakeholders y usuarios, mapa de fricciones, UX Value Proposition Canvas y roadmap del proyecto.
  3. Diseño UX/UI · Diseño de la experiencia: Taller creativo, moodboard, wireframes, UI flows y prototipos navegables pixel-perfect que definieron el sistema de diseño.
  4. Desarrollo · Construcción del software: Front end (React Native + React JS), backend e infraestructura en la nube e integración de APIs (Gemini, Maps, CRM) con CI/CD y pruebas unitarias.
  5. Quality Assurance · Aseguramiento de calidad: QA de diseño, funcional, responsive y cross-browser (Chrome, Firefox, Safari y Edge), más pruebas de seguridad.
  6. Entrega del MVP: Sitio Web, App y Consola entregados y documentados.

Taller de ideación

Presencial · 3 horas

Sesión presencial para convertir la lista de ideas Future Proof en un plan priorizado. Partimos de lo que aprendimos con el MVP, filtramos las ideas con los perfiles reales del ecosistema y las clasificamos por necesidad del usuario y por viabilidad técnica, para decidir qué entra al MMP, qué al MLP y qué se replantea.

  • Filtrar y depurar las ideas Future Proof de App, Sitio Web y Consola.
  • Construir una matriz de necesidades que conecte cada idea con un perfil y un problema real.
  • Clasificar las ideas en una matriz de viabilidad técnica y de usuario.
  • Salir con una priorización MMP / MLP, responsables y siguientes pasos.

Matriz de viabilidad técnica y de usuario

  • Quick wins (Alto valor · baja complejidad): Entran primero (MMP).
  • Apuestas estratégicas (Alto valor · alta complejidad): Se planean por fases (MMP / MLP).
  • Mejoras incrementales (Bajo valor · baja complejidad): Se agendan cuando haya capacidad.
  • Replantear (Bajo valor · alta complejidad): Se descartan o se redefinen.

Pendientes generales y planeación de lanzamiento

Pendientes generales

  • Logos completos para el sitio web (Pendiente): Faltan los logotipos finales de aliados y organizaciones que aparecen en el sitio.
  • Conexión de infraestructura y hosting (Pendiente): Conectar la infraestructura y el hosting definitivos para publicar los ambientes de producción.
  • Correos diferenciados por perfil (Pendiente): Faltan los correos transaccionales propios para los tres tipos de usuario —administradores (por rol), profesionales y pacientes—; cada perfil debe recibir sus propios correos.

  • Multi-usuarios por perfil (En desarrollo): Separar los perfiles para que un mismo usuario no pueda ser paciente y médico a la vez.

Glosario

React Native
Framework para construir la App Móvil (iOS / Android) desde una base de código.
React JS
Librería con la que se desarrolla el frontend de la Consola Administrativa y el sitio.
API REST
Interfaz del backend por la que viajan los datos entre App, Web y Consola.
Swagger / Postman
Herramientas para documentar y probar los endpoints de la API.
CI/CD
Integración y entrega continuas: automatiza pruebas y despliegues del código.
RBAC
Control de acceso basado en roles: permisos por tipo de usuario en la consola.
JWT
Token firmado que autentica sesiones (access + refresh) de forma segura.
OTP
Código de un solo uso para verificar identidad en el acceso.
Gemini API
Motor de IA de Google Cloud que impulsa la IA Consultora (triaje y orientación).
Google Maps API
Servicio de mapas para la visualización geolocalizada del directorio.
CRM / ERP
Integración con el sistema de registros actual de [Cliente] (citas y expedientes).
PostgreSQL / Redis
Base de datos relacional y cache en memoria del backend.
WCAG 2.1 AA
Estándar de accesibilidad web exigido por el perfil de los usuarios finales.
